# Blender Procedural MCP — Current-State Audit and Roadmap

Audit date: 2026-09-04. Target: Blender 5.1+; runtime verification used Blender 5.2.1 LTS where noted.

## Executive finding

The server is no longer a small modeling bridge. The reviewed snapshot exposes 282 MCP tools before this work and already implements all planned Geometry Nodes, cloth, liquid, rigid-body, and retopology tools, plus broad camera, rigging, lighting, PBR, native geometry, animation, scene, and render foundations. The current architecture should be extended, not replaced.

This work adds two tools (`get_shader_node_type_info`, `patch_shader_graph`) and extracts a shared Blender-side node-graph mutation engine used by Geometry Nodes and shader graphs. The resulting surface has 284 registered tools. Arbitrary `execute_blender_code` remains removed from the production API.

## Evidence and architecture reviewed

- Public surface: every module under `server/tools`, the final metadata pass, all 282 pre-change registrations, schemas, response envelopes, and read-only classification.
- Blender runtime: all handler packages, command dispatch, target discovery, context restoration, transaction rollback, addon protocol/versioning, provider isolation, and main-thread queueing.
- Verification assets: 441 baseline tests, Blender smoke scripts, nine existing domain plans, Git history through `de6b9e4`, and the complete uncommitted implementation snapshot present on 2026-09-04.
- Architecture: FastMCP async tools validate Pydantic input, offload blocking socket I/O, dispatch NDJSON commands to Blender, execute all `bpy` work on Blender's main thread, wrap mutations in rollback/undo bookkeeping, then normalize results through the shared envelope.
- Official sources checked: Blender 5.1 manual/API pages for Mesh, Curve/Curves/Surface, PointCloud, Volume/OpenVDB, modifiers, Geometry Nodes and zones, Material/World/Light shader trees, images/UV/UDIM/baking, armatures/constraints/drivers/Actions/NLA, cameras/stereo/movie tracking, particles, force fields, cloth, soft body, dynamic paint, fluid gas/liquid, rigid bodies, light probes, scenes/view layers, rendering, and compositing. Blender 5.2 runtime RNA confirmed the corresponding target APIs and operators where 5.1 behavior needed concrete validation.

| Materials and textures | Material/image inventory, Principled creation/configuration, assignment, semantic PBR texture sets, mapping, UV maps/seams/unwrap/optimization/inspection, bake, preview, validation | Keep. These high-level tools remain preferable to raw graph operations for common PBR work. |
| Rigging and animation | Armature/bone editing, skin weights, constraints, IK/FK, spline IK, B-Bones, pose controls, generic Action/keyframe/NLA/driver tools, object transform keyframes | Keep. | Cameras and lighting | Camera creation/configuration/DOF/aim/framing/rigs/shots; light/world creation/configuration/linking/quality/color/preview/validation | Keep. Missing advanced workflows should call these foundations. |
| Physics | Complete cloth, liquid, and rigid-body setup/inspection/validation/cache/sample/delivery families plus scene gravity | Keep. They provide the correct cache-aware and evidence-based pattern for future solvers. |
| Scene/render/assets | Declarative geometry objects, transforms, instances, collections, hierarchy, constraints, render settings, view layers/passes, bounded render, Poly Haven, Sketchfab | Keep. Provider tools remain optional and network work remains separated from Blender mutations. |

## Recommended roadmap

1. **P0 — Finish safe graph and deformation foundations:** ship the implemented shader graph tools; add compositor graph patching, shape-key lifecycle, Curve/Curves editing, and type-specific object inspection. Keep all graph mutations copy-on-write and runtime-discovered.
2. **P1 — Complete Blender-native simulation coverage:** refactor fluid internals for gas, then add soft body and dynamic paint using the existing cache/validation contracts. Add legacy particles only as a compatibility tier; prefer Geometry Nodes for new scatter and hair.
3. **P1 — Production look-development:** add texture storage/UDIM/projection/density, managed lighting rigs/light shaders/light groups/probes/atmosphere, and quantitative render analysis.
4. **P2 — Camera/character delivery:** add stereo/tracking, generic evaluated animation bake, retargeting, pose assets, optional Rigify, skin-deformation analysis, and explicit rig export.
5. **Continuous:** extend Blender smoke coverage for each operator/context-dependent path; keep old public names as wrappers during consolidation; bump the addon protocol for every handler-surface change; do not restore arbitrary Python execution.
